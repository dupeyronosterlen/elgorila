CÓMO FUNCIONA LA VENTA (para todo el equipo)
────────────────────────────────────────────
  1. Cada MIÉRCOLES tiene su propio cupo de 325 (inventario independiente).
  2. El sitio y la boletera NO pueden vender más allá del cupo: el Worker rechaza
     la compra con «No hay suficientes lugares».
  3. La galería NO se vende en línea mientras quede platea.
  4. Tras pagar (Stripe o efectivo en boletera), el sistema emite:
       · CERT-ORD-…  (orden / compartir / invitaciones)
       · CERT-…      (cada boleto individual)
       · Folio puerta (solo staff, en admin o verificar)
  5. No hay «certificados infinitos»: 1 certificado = 1 boleto pagado y contado
     en el inventario de esa fecha.

CLOUDFLARE — QUÉ REVISAR (checklist operativo)
──────────────────────────────────────────────
  A) PAGES (sitio elgorilateatro.com.mx)
     Dashboard → Workers & Pages → proyecto del sitio → Deployments
     · Debe haber deploy reciente tras push a GitHub (main)
     · Si no hay CI: Deploy manual o conectar repo dupeyronosterlen/elgorila

  B) WORKER (API elgorila-api)
     Workers & Pages → elgorila-api → Deployments
     · Versión activa reciente (panel reclamos, cupones, etc.)
     · Deploy local: npx wrangler deploy

  C) KV — INVENTARIO (namespace 5c1712aba9…)
     Claves importantes:
       wilberto:config ............... platea 250 + galeria 75 (325)
       wilberto:funciones:activas .... 13 fechas jul–sep (todas en venta)
       wilberto:funcion:2026-07-08 ... inventario de ESA fecha (vendidos/reservados)

     Actualizar config si cambian butacas:
       node scripts/init-config.js wilberto > /tmp/wilberto-config.json
       npx wrangler kv key put "wilberto:config" --binding INVENTARIO \
         --path /tmp/wilberto-config.json --remote

  D) KV — VENTAS (namespace 1a9c033a4…)
     · ventas, certificados, índices — no tocar manualmente salvo emergencia

  E) SECRETS (Worker → Settings → Variables and Secrets)
     Obligatorios: JWT_SECRET, STRIPE_SECRET_KEY, STRIPE_WEBHOOK_SECRET,
                   RESEND_API_KEY, ADMIN_* (usuarios)
     Opcionales: REPORTE_TOKEN, MAKE_WEBHOOK_URL

  F) STRIPE
     Webhook → checkout.session.completed + expired → URL del Worker /api/webhook

WALLET (Google + Apple) — secrets en Cloudflare Worker
──────────────────────────────────────────────────────
  Endpoint: GET /api/wilberto/venta/{CERT}/wallet?boleto=N
  Botones en compartir-boleto.html (se activan al configurar secrets).

  GOOGLE WALLET (recomendado primero)
    1. Google Pay & Wallet Console → crear emisor → anotar Issuer ID
    2. Crear clase genérica: {issuerId}.elgorila_boleto
    3. Service Account con rol «Wallet Object Issuer» → descargar JSON
    4. wrangler secret put GOOGLE_WALLET_ISSUER_ID   → 3388000000023157310 (ya en Worker)
    5. wrangler secret put GOOGLE_WALLET_SA_JSON   (JSON service account)
       O: ./scripts/setup-google-wallet-secrets.sh /ruta/al.json
    6. wrangler deploy

  APPLE WALLET (cuenta developer Apple)
    1. Certificates → Pass Type ID (ej. pass.com.elgorilateatro.boleto)
    2. Generar certificado .p12 + descargar WWDR G4
    3. Secrets:
         APPLE_PASS_TYPE_ID
         APPLE_TEAM_ID
         APPLE_PASS_P12_BASE64   (base64 del .p12)
         APPLE_PASS_P12_PASSWORD
         APPLE_WWDR_PEM          (contenido del certificado WWDR)
    4. Falta implementar firma .pkpass en worker (Apple aún en stub)
